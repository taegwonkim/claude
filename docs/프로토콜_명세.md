# 프로토콜 명세

## 1. PC ↔ MCU 프레임 포맷 (USART3 / USB CDC 공용)

**PC와 MCU 사이(USART3, USB CDC)에서 주고받는 모든 메시지는 아래 프레임 포맷을 따릅니다**
(ESP32 AT 커맨드/USART1, FPGA↔MCU/USART2, ESP32 경유 TCP 서버 페이로드에는 적용되지 않습니다 —
그쪽은 각각 §3, §4에 설명된 기존 포맷을 그대로 사용합니다):

```
STX(0x02) + Data1,Data2,...,DataN + CR(0x0D) + LF(0x0A)
```

- 프레임은 항상 `STX`(0x02) 1바이트로 시작합니다.
- 이어서 필드들을 콤마(`,`)로 구분해 나열합니다 (`Data1,Data2,...,DataN`). 필드 개수는
  메시지 종류에 따라 다르며, 첫 번째 필드(`Data1`)가 메시지/커맨드 종류를 나타냅니다.
- 프레임은 `CR`(0x0D) 다음 `LF`(0x0A)로 끝납니다.
- `STX`가 없는 라인(잡음, 전원 인가 시 깨진 바이트 등)은 양쪽 모두 무시합니다.
- USART3와 USB CDC는 완전히 독립적인 입력 소스로 동작하지만(각각 커맨드 입력 가능), 응답/측정값/
  이벤트 **출력은 두 채널 모두에 항상 동일하게 미러링**됩니다.
- 구현: MCU 측 프레임 빌드/파싱은 `firmware/Core/Inc/pc_frame.h`+`firmware/Core/Src/pc_frame.c`
  (`PcFrame_Wrap`/`PcFrame_Parse`), PC 측은 `Stm32Protocol.cs`(`TryParseFrame` 등)가 담당합니다.

### PC → MCU 커맨드

| 프레임 (STX 이후 콤마 필드) | 설명 |
|---|---|
| `SET,SSID,<string>` | AP SSID 설정 (최대 31자) |
| `SET,PASS,<string>` | AP 비밀번호 설정 (최대 63자) |
| `SET,SERVER_IP,<a.b.c.d>` | 목적지 서버 IP |
| `SET,SERVER_PORT,<0-65535>` | 목적지 서버 포트 (기본 50001) |
| `SET,DHCP,ON` | ESP32 DHCP 클라이언트 사용 |
| `SET,DHCP,OFF` | 정적 IP 사용 (아래 IP/GATEWAY/MASK 필요) |
| `SET,IP,<a.b.c.d>` | (DHCP OFF일 때) ESP32 정적 IP |
| `SET,GATEWAY,<a.b.c.d>` | (DHCP OFF일 때) 게이트웨이 |
| `SET,MASK,<a.b.c.d>` | (DHCP OFF일 때) 넷마스크 |
| `SAVE` | 현재 설정을 W25Q40 플래시에 저장 + WiFi 재접속 트리거 |
| `GET,CONFIG` | 현재 설정(비밀번호는 마스킹) 조회 |
| `STATUS` | WiFi/TCP 연결 상태 조회 |
| `HELP` | 커맨드 목록 조회 |

예: SSID를 "myssid"로 설정 → 프레임 바이트열은 `0x02 'S' 'E' 'T' ',' 'S' 'S' 'I' 'D' ',' 'm' 'y' 's' 's' 'i' 'd' 0x0D 0x0A`.

### MCU → PC 응답 / 비동기 메시지

메시지 종류는 **첫 번째 필드로 구분**합니다. `OK`/`ERR`/`SAVED`/`CONFIG`/`HELP`는 PC가 보낸
커맨드에 대한 직접 응답이고, `STATUS`/측정값(아래 §2)/`EVENT`는 PC 커맨드 없이도 MCU가 자체
판단으로 보내는 비동기 메시지입니다(PC 쪽 파서는 이 둘을 구분해서 처리해야 함 — 후자가 응답
대기 중에 섞여 들어와도 무시해야 커맨드-응답 매칭이 깨지지 않습니다. `Stm32Commands.cs`의
`SendAndWaitReplyAsync`가 이 화이트리스트 방식으로 구현되어 있습니다):

| 프레임 | 의미 | 성격 |
|---|---|---|
| `OK` | `SET,...` 성공 | 커맨드 응답 |
| `ERR,<reason>` | 실패 (예: `ERR,INVALID_IP`, `ERR,SSID_TOO_LONG`, `ERR,UNKNOWN_COMMAND`, `ERR,BAD_FRAME`, `ERR,STATIC_IP_INCOMPLETE`, `ERR,QUEUE_FULL`) | 커맨드 응답 |
| `SAVED` | `SAVE` 성공 (큐 적재 성공 시점 응답, 실제 플래시 쓰기는 Config_Task가 비동기 수행) | 커맨드 응답 |
| `CONFIG,<ssid>,<pass_masked>,<server_ip>,<server_port>,<ON/OFF>,<ip>,<gateway>,<mask>` | `GET,CONFIG` 응답. `<pass_masked>`는 항상 `****` (실제 비밀번호는 절대 돌려주지 않음) | 커맨드 응답 |
| `HELP,<text>` | `HELP` 응답 (커맨드 요약, 필드 내부에 콤마는 없음) | 커맨드 응답 |
| `STATUS,<번호>` | ESP32 상태. `STATUS` 커맨드 응답 **겸** 주기적 브로드캐스트 (아래 참고) | 비동기 |
| `<DC IP>,<MAC>,data1,...,data6` | 측정값 (아래 §2 참고, "DATA" 같은 태그 없이 바로 IP로 시작) | 비동기 |
| `EVENT,<name>` | 비동기 이벤트 (아래 표 참고) | 비동기 |

`GET,CONFIG` 응답 예 (실제로는 STX/CRLF로 감싸인 한 프레임):
```
CONFIG,myssid,****,192.168.0.10,50001,OFF,192.168.0.50,192.168.0.1,255.255.255.0
```

`SET ...`은 RAM 상의 임시(pending) 설정만 바꾸며, `SAVE`를 호출해야 플래시 반영 + WiFi 재접속이
일어납니다. (실수로 매 SET마다 플래시 쓰기/삭제가 일어나 플래시 수명이 줄어드는 것을 방지)

### ESP32 상태 프레임 (`STATUS,<번호>`)

MCU(`firmware/Core/Src/app_freertos.c`의 `Esp32TaskBody`)는 측정값을 보내는 사이사이에, **2초 간격으로**
(`APP_ESP32_STATUS_BROADCAST_MS`, `app_config.h`) ESP32의 현재 상태를 자동으로 PC에 보냅니다.
PC가 `STATUS` 커맨드를 명시적으로 보내면 그 즉시 한 번 더 응답합니다(같은 프레임 형식). `<번호>`는
`Esp32_LinkState_t` enum 값 그대로입니다:

| 번호 | 의미 |
|---|---|
| `0` | WiFi 연결 끊김 (`ESP32_LINK_DOWN`) |
| `1` | WiFi는 연결됨, 서버 TCP는 미연결 (`ESP32_WIFI_UP`) |
| `2` | WiFi + 서버 TCP 모두 연결됨 (`ESP32_TCP_UP`) |

예: `STATUS,2` → STX/CR/LF로 감싸면 `0x02 'S' 'T' 'A' 'T' 'U' 'S' ',' '2' 0x0D 0x0A`.

### 비동기 이벤트 프레임 (MCU → PC, 커맨드 응답과 별개로 언제든 발생 가능)

WiFi/TCP 연결 상태가 바뀔 때마다(수동 SAVE 이후뿐 아니라, AP 전파 문제 등으로 **끊어졌다가
MCU가 AT 커맨드로 자동 재접속을 시도/성공할 때도**) 아래 프레임이 PC로 미러링됩니다
(`firmware/Core/Src/app_freertos.c`의 `ReportLinkStateChange()`):

| 이벤트 | 의미 |
|---|---|
| `EVENT,WIFI_DISCONNECTED` | ESP32로부터 `WIFI DISCONNECT` URC 수신 (WiFi/TCP 모두 끊김) |
| `EVENT,WIFI_CONNECTED` | WiFi(AP) 연결 성공 (`AT+CWJAP` 성공, TCP는 아직) |
| `EVENT,TCP_CONNECTED` | 서버로 TCP 연결 성공 (`AT+CIPSTART` 성공) — 이 상태에서만 측정값이 서버로 전송됨 |
| `EVENT,TCP_CLOSED` | WiFi는 유지된 채 TCP만 끊김(`CLOSED` URC) |

재접속 동작: MCU는 `WIFI_DISCONNECTED` 또는 `TCP_CLOSED` 상태를 감지하면 5초 간격으로
저장된 마지막 설정을 사용해 `AT+CWJAP`(WiFi부터 끊긴 경우) 또는 `AT+CIPSTART`(TCP만 끊긴 경우)를
재시도합니다. 재접속에 성공하면 `EVENT,WIFI_CONNECTED`/`EVENT,TCP_CONNECTED`가 다시 출력됩니다.
PC에서 별도 커맨드를 보낼 필요 없이 MCU가 자동으로 수행합니다.

## 2. 측정값 출력 포맷

**PC(USART3+USB, §1 프레임 포맷)**: 한 트리거당 한 프레임. "DATA" 같은 태그 없이 바로 DC(이 장치)의
IP/MAC으로 시작합니다(`firmware/Core/Src/fpga_link.c`가 `MeasurementMsg_BuildPcCsvFields()`로 만들고
`PcComm_BroadcastFrame()`으로 STX/CR/LF를 씌워 전송):
```
<dc_ip>,<dc_mac>,data1,data2,data3,data4,data5,data6
```
- `dc_ip`: 이 STM32+ESP32 장치의 ESP32 station IP (예: `192.168.0.42`). WiFi 연결 후
  `Esp32_QueryNetInfo()`(`firmware/Core/Src/esp32_at.c`, `AT+CIFSR` 사용)가 조회해 캐시해두고, 매 측정값
  프레임마다 그 캐시값을 그대로 붙입니다. WiFi 연결 전에는 `0.0.0.0`이 나갑니다.
- `dc_mac`: 같은 방식으로 캐시된 ESP32 station MAC 주소(예: `ca:fe:ba:be:12:34`). WiFi 연결 전에는
  `00:00:00:00:00:00`.
- `data1`..`data6`: USART2로 수신한 ADC 샘플 값 6개(부호 없는 정수, 10진수) —
  `FPGA_ADC_SAMPLE_COUNT`(`app_config.h`)가 `6`으로 고정되어 있어야 합니다.

예: `192.168.0.42,ca:fe:ba:be:12:34,101,102,103,104,105,106`

**서버(ESP32 경유 TCP, `AT+CIPSEND`)**: PC 시리얼 링크와는 별개로, MCU 내부에서 관리하는
`seq`(트리거 시퀀스 번호)/`timestamp_ms`(캡처 시각)를 포함한 기존 공백 구분 포맷을 그대로
유지합니다(`firmware/Core/Src/measurement_msg.c`의 `MeasurementMsg_BuildDataLine()`,
`firmware/Core/Src/app_freertos.c`의 `Esp32_TcpSend()`가 사용):
```
DATA <seq> <timestamp_ms> <sample0> <sample1> ... <sampleN-1>\r\n
```
PC 프레임에는 `seq`/`timestamp_ms`가 포함되지 않습니다(DC IP/MAC + 샘플 6개로 대체) — 두 링크가
서로 다른 포맷을 쓰는 점에 유의하세요.

## 3. MCU ↔ FPGA: 측정 개시 커맨드 및 트리거/ADC 프레임

FPGA는 자체적으로 ADC를 읽어(FPGA에 ADC가 직결) 그 값을 MCU로 넘겨줍니다. USART2는 이제
양방향으로 사용됩니다: MCU→FPGA(PA2, 측정 개시 커맨드 1회)와 FPGA→MCU(PA3, 트리거 후
ADC 측정값 라인, 매 트리거마다). 트리거(EXTI)와 ADC 데이터(USART2 RX)는 서로 다른 신호선을
사용합니다.

0. **부팅 후 1회, MCU → FPGA 측정 개시 커맨드**: `FpgaLink_Init()`이 USART2 TX(PA2)로 아래
   프레임을 한 번 전송합니다(PC↔MCU용 STX+CRLF 프레이밍과 형태는 같지만 §1과 별개로 USART2
   전용, `FPGA_START_CMD`/`app_config.h`에 정의):
   ```
   STX(0x02) + "START" + CR(0x0D) + LF(0x0A)
   ```
   FPGA는 이 커맨드를 수신한 시점부터 주기적으로 트리거+ADC 값을 보내기 시작하는 것으로
   가정합니다(그 이전에는 트리거를 보내지 않아야 함).
1. FPGA가 GPIO(PH1, 핀 라벨 `FROM_FPGA`)를 **falling edge**로 1펄스 구동 → MCU EXTI 인터럽트 발생, MCU가 즉시
   FPGA_Task를 깨우고 USART2 라인 수신 대기(타임아웃 `FPGA_LINE_TIMEOUT_MS`, 기본 200ms)를 시작.
2. FPGA는 트리거 직후(수 ms 이내 권장) ADC 측정값을 **USART2**(115200 8N1)로 아래 ASCII 라인
   포맷으로 전송:
   ```
   ADC <seq> <sample0>[ <sample1> ... <sampleN-1>]\r\n
   ```
   - `seq`: FPGA가 매기는 트리거 시퀀스 번호(필수, 10진수). MCU는 이 값을 서버로 보내는 TCP
     `DATA <seq> ...` 라인(§2)에 사용 — PC로 보내는 프레임(§2)에는 포함되지 않는다.
   - `sampleX`: 10진수 ADC 코드값(부호 없는 정수). 샘플 개수는 `FPGA_ADC_SAMPLE_COUNT`(기본 6개,
     PC 프레임의 data1..data6에 대응)와 정확히 일치해야 함(부족하면 해당 트리거를 파싱 실패로 드롭).
3. MCU(`fpga_link.c`)는 라인을 파싱해 `xQueue_Measurement`에 `MeasurementMsg_t`를 push.
   타임아웃 내에 라인이 도착하지 않으면 해당 트리거는 드롭하고 에러 카운터만 증가시킨 뒤 다음
   트리거를 대기합니다(재전송 요청 없음 — 필요 시 프로토콜 확장 가능).

> **FPGA 설계팀과 반드시 확정해야 할 사항**: 트리거 후 UART 데이터 전송까지의 지연시간, 라인
> 종료 문자(`\r\n` 고정 여부), 샘플 개수/폭, seq 필드 포함 여부. 본 문서의 값은 초기 제안치이며
> `app_config.h`(`FPGA_ADC_SAMPLE_COUNT`)와 `fpga_link.c`에서 함께 조정하세요.

## 4. ESP32 AT 커맨드 시퀀스 (USART1, 115200 8N1)

부팅/설정변경 시 WiFi 연결 절차:
```
AT                                   -> OK                (모듈 응답 확인)
ATE0                                 -> OK                (에코 끄기)
AT+CWMODE=1                          -> OK                (Station 모드)
AT+CWJAP="<ssid>","<pass>"           -> WIFI CONNECTED / WIFI GOT IP / OK
  (DHCP=OFF인 경우, CWJAP 이전에)
AT+CWDHCP=1,0                        -> OK                (station DHCP client off)
AT+CIPSTA="<ip>","<gateway>","<mask>"-> OK
  (DHCP=ON인 경우)
AT+CWDHCP=1,1                        -> OK                (station DHCP client on, 기본값)
AT+CIPMUX=0                          -> OK                (단일 연결 모드)
AT+CIPSTART="TCP","<server_ip>",<port> -> CONNECT / OK
```
데이터 전송(측정값 발생 시마다):
```
AT+CIPSEND=<len>                     -> OK, "> " 프롬프트
<len바이트 payload (DATA ... \r\n)>  -> SEND OK
```
비동기 URC(언제든 수신 가능, `esp32_at.c`가 백그라운드로 파싱):
- `WIFI DISCONNECT` / `WIFI CONNECTED` / `WIFI GOT IP`
- `CLOSED` (TCP 연결 끊김 → 재연결 로직 트리거)
- `+IPD,<len>:<data>` (서버 → MCU 하향 데이터, 필요시 확장 처리)

## 5. W25Q40CLSNIG 플래시 메모리 맵 (SPI2)

W25Q40 용량: 4Mbit = 512KB, 섹터 크기 4KB.

| 주소 범위 | 용도 |
|---|---|
| `0x000000` ~ `0x000FFF` (섹터0, 4KB) | 네트워크 설정 레코드 (`NetConfig_t` + CRC32), 아래 참고 |
| `0x001000` ~ | (예비, 향후 확장용, 미사용) |

설정 저장은 **wear-leveling 없이 단일 섹터**를 사용합니다(설정 변경 빈도가 낮으므로 충분).
쓰기 절차: 섹터 Erase(4KB) → 구조체 전체를 Page Program(최대 256B 단위 분할)으로 기록.
읽기 시 CRC32 불일치면 "설정 없음"으로 간주하고 WiFi 연결을 시도하지 않고 PC 입력을 대기합니다.

`NetConfig_t` 레이아웃은 `firmware/Core/Inc/net_config_store.h` 참고 (버전 필드 포함, 향후 필드 추가 대비).
