# SLAC 이후 high level 통신 — IPv6 · SDP · V2GTP · DIN SPEC 70121

이 문서는 SLAC 매칭 다음 단계인 **DC 충전 high level 통신(DIN SPEC 70121)** 구현을 설명합니다.
충전기(SECC)와 차량(EVCC) 양쪽이 모두 들어 있고, PC 테스트에서 두 프로세스가 실제 lwIP IPv6/TCP로
세션 전체(SDP → … → CurrentDemand → SessionStop)를 주고받는 것까지 확인했습니다.

> **실제 차량·충전기와의 상호 운용 시험은 아직 하지 않았습니다.** 타이밍 값과 일부 필드(PMax 단위 등)는
> 인증 대상 규격판과 대조해서 확인하세요(`V2G/v2g_conf.h`).
> **전력부는 시뮬레이션입니다.** 고전압을 다루는 실제 하드웨어 훅으로 바꾸기 전에는 충전에 쓰면 안 됩니다.

## 1. 계층과 파일

```
 app_evse.c / app_ev.c        CP, SLAC 매칭 → SECC / EVCC 시작, 분리 시 정지
 ─────────────────────────────────────────────────────────────────────────
 V2G/din_secc.c   (충전기)    DIN 70121 서버 상태 머신, 시퀀스 검사, 응답 생성
 V2G/din_evcc.c   (차량)      DIN 70121 클라이언트 상태 머신, 요청 순서, 타임아웃
 V2G/v2g_hw.h, v2g_sim.c      하드웨어 훅 (전력 모듈/절연/CP, BMS/접촉기/S2) + 시뮬레이션
 V2G/v2g_codec.c              EXI 인코드/디코드 (libcbv2g), PhysicalValue 변환
 V2G/v2gtp.c                  V2GTP 8바이트 헤더, TCP 스트림 → 메시지 재조립
 V2G/v2g_sdp.c                SDP (UDP 15118): 충전기 응답 / 차량 탐색·재시도
 V2G/v2g_netif.c              lwIP netif: QCA7005 드라이버 ↔ lwIP, IPv6 link-local
 V2G/lwipopts.h               lwIP 설정 (IPv6 전용, NO_SYS)
 ─────────────────────────────────────────────────────────────────────────
 Middlewares/Third_Party/LwIP     lwIP 2.1.2 (core, ipv6, ethernet 만)   BSD-3-Clause
 Middlewares/Third_Party/cbv2g    libcbv2g (common, app_handshake, din)  Apache-2.0
 ─────────────────────────────────────────────────────────────────────────
 PLC/qca7k.c  →  SPI  →  QCA7005
```

**프레임 경로** (`Core/Src/app_plc.c`)
- 수신: 이더타입 `0x88E1`(HomePlug MME) → SLAC/모뎀 처리, 그 외(IPv6 `0x86DD`) → `v2g_netif_input()` → lwIP
- 송신: lwIP `linkoutput` → `qca7k_send()`
- 매 루프 `v2g_netif_poll()` 이 lwIP 타이머(TCP 재전송, ND, MLD)를 돌립니다

## 2. 순서 (실제 PC 테스트 로그)

```
EVSE [SECC] waiting for the EV (TCP port 61851)
EV   [SDP]  -> SECC Discovery Request to ff02::1:15118
EV   [SDP]  <- response: SECC [FE80::E5:FF:FE00:1]:61851 security 0x10
EV   [EVCC] TCP connected to SECC
EVSE [SECC] <- supportedAppProtocolReq: urn:din:70121:2012:MsgDef 2.0 id 1 prio 1
EV   [EVCC] <- supportedAppProtocolRes: DIN 70121 accepted
EV   [EVCC] <- SessionSetupRes: session 51FF4AEC29CDBAAB
EV   [EVCC] -> ServiceDiscoveryReq / ServicePaymentSelectionReq (ExternalPayment)
EV   [EVCC] <- ContractAuthenticationRes: authorized
EVSE [SECC] <- ChargeParameterDiscoveryReq EV max 420 V 100 A SOC 30 %
EV   [EVCC] <- ChargeParameterDiscoveryRes: EVSE max 500 V 125 A 50000 W -> close S2 (state C)
EVSE [SECC] <- CableCheckReq: insulation test started
EV   [EVCC] <- CableCheckRes: insulation OK after 1100 ms -> PreCharge
EV   [EVCC] <- PreChargeRes: EVSE 344.0 V, battery 344.0 V -> PowerDelivery
EV   [EVCC] <- PowerDeliveryRes: close contactors, charging
EV   [EVCC] CurrentDemand #21: EVSE 400.0 V 80.0 A, SOC 34 %
EV   [EVCC] stop charging (battery full) after 42 CurrentDemand cycles, SOC 40 %
EV   [EVCC] <- PowerDeliveryRes: charging stopped, open contactors
EV   [EVCC] <- WeldingDetectionRes: 0.0 V -> SessionStop
EVSE [SECC] -> SessionStopRes, session done (81 requests)
```

| 단계 | 충전기 (din_secc.c) | 차량 (din_evcc.c) |
|---|---|---|
| IPv6 | MAC → fe80:: 주소, DAD 1회 (약 1 s) | 같음. DAD 끝난 뒤 SDP 시작 |
| SDP | UDP 15118 수신, 자기 주소·포트 61851·보안 0x10(TLS 없음) 응답 | `ff02::1` 로 250 ms 간격 최대 50회 |
| TCP | 61851 listen, 한 번에 한 대 | SDP 응답 주소로 connect (2 s) |
| supportedAppProtocol | DIN 네임스페이스·메이저 2 를 찾아 선택 | DIN 하나만 제안 |
| SessionSetup | 8바이트 난수 세션 ID 발급, 이후 불일치 시 `FAILED_UnknownSession` | EVCCID = MAC |
| ServiceDiscovery | ExternalPayment, `DC_extended` | ExternalPayment 있는지 확인 |
| ContractAuthentication | `hw.authorized()` 가 1 이 될 때까지 Ongoing | 100 ms 간격 반복 |
| ChargeParameterDiscovery | 한계값 + SAScheduleList(24 h, PMax) | 끝나면 **S2 닫음(상태 C)** |
| CableCheck | CP 상태 C 확인 → 절연 검사 시작 → Valid 가 될 때까지 Ongoing | 최대 38 s |
| PreCharge | 출력 = EV 목표 전압, 전류 2 A 이하 | 차이 20 V 이하면 다음, 최대 7 s |
| PowerDelivery(start) | 충전 단계로 | **접촉기 닫음** |
| CurrentDemand | 목표 V/I 를 한계값으로 제한해 출력, 현재값·제한 플래그 응답 | 100 ms 주기, 응답 250 ms 이내 |
| 종료 조건 | `din_secc_request_stop()` → `StopCharging` 알림 | 배터리 완료 / EV 요청 / EVSE 알림 |
| PowerDelivery(stop) | 출력 끔 | 접촉기 열림 |
| WeldingDetection | 현재 전압 응답 | 40 V 미만 또는 20회 |
| SessionStop | 응답 후 TCP 종료 | **S2 열림**, TCP 종료 |

어느 단계든 실패하면 차량은 **접촉기·S2 를 열고** TCP 를 끊으며, 충전기는 **출력을 끄고** 이벤트를 보냅니다.

## 3. 하드웨어 훅 — 제품으로 만들 때 바꿀 부분

`V2G/v2g_hw.h` 의 함수 포인터만 채우면 프로토콜 코드는 그대로 씁니다.

### 충전기 `secc_hw_t`
| 훅 | 할 일 | 지금 (v2g_sim.c) |
|---|---|---|
| `limits` | 최대/최소 전압·전류·전력, 리플 | 500 V / 125 A / 50 kW |
| `authorized` | RFID·결제 완료 여부(EIM) | 항상 1 |
| `cp_state_c` | CP 상태 C/D (S2 닫힘) | **실제 CP 측정값** (`app_evse.c`) |
| `isolation_start/result` | 절연 감시 장치(IMD) | 1 s 뒤 Valid |
| `output` | 전력 모듈 on/off, 전압, 전류 제한 (대개 CAN) | 400 V/s 로 전압 추종 |
| `measure` | 출력 전압·전류 측정 | 모델값 |

### 차량 `evcc_hw_t`
| 훅 | 할 일 | 지금 (v2g_sim.c) |
|---|---|---|
| `limits` | 최대 전압·전류·전력, 용량, Full/Bulk SOC | 420 V / 100 A / 40 kW / 300 Wh |
| `battery_voltage`, `soc` | BMS 값 | 320~400 V, 30 % 시작 |
| `target_current/voltage` | BMS 요청 | 80 A, 400 V |
| `charge_complete` | 충전 종료 | SOC ≥ 40 % |
| `s2` | CP S2 스위치 | **실제 PE11 핀** (`app_ev.c`) |
| `contactor` | DC 접촉기 | 모델 |

데모용 배터리는 용량이 300 Wh 라서 30 % → 40 % 충전이 약 4초에 끝납니다.

## 4. 보드 두 장으로 시험하기

1. 충전기 보드: `make ROLE=EVSE`, 차량 보드: `make ROLE=EV`
2. 두 QCA7005 의 PLC 결합부를 CP·PE 선으로 연결하고, CP ±12 V 회로를 연결합니다
3. 차량 쪽에서 S2 가 닫히면 충전기 ADC 가 상태 C 를 읽어야 CableCheck 가 진행됩니다
4. 로그(115200)에서 `[SECC]` / `[EVCC]` 메시지와 2초마다 나오는 상태 줄을 확인합니다 (아래는 형식 예시)
   ```
   ... | CP C 5980 mV 5.0 % | SLAC MATCHED | DIN SESSION 400 V 80 A      (충전기)
   ... | CP C 5990 mV 5.0 % | SLAC MATCHED | DIN SESSION CurrentDemand SOC 35 %   (차량)
   ```
5. 세션이 끝나면 충전기는 PWM 을 끄고, 커넥터를 뽑았다 다시 꽂아야(상태 A → B) 새 세션이 시작됩니다

## 7. 아직 없는 것

- **ISO 15118-2 / -20**: libcbv2g 에 코덱이 있으므로(`iso_2`, `iso_20`) 같은 구조로 상태 머신을 추가하면 됩니다.
  supportedAppProtocol 에서 우선순위로 고르게 됩니다
- **TLS / Plug & Charge**: ISO 15118-2 PnC, -20 에 필요 (mbedTLS + 인증서). 지금 SDP 는 항상 "TLS 없음" 으로 응답합니다
- **AC 충전 (ChargingStatus)**: DIN 70121 은 DC 전용입니다
- **CM_VALIDATE**, 다중 차량 동시 접속(충전기 한 대당 한 연결만 받음)
- 실제 차량과의 상호 운용 시험, 규격 타이밍 검증
